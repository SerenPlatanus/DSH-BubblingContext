# BubblingContext

DSH 轨迹与上下文的实时气泡可视化插件，当前版本 0.4.1。缩放和平移按动画帧合并，不触发整图 React 重渲染；验证记录见 [PERFORMANCE.md](PERFORMANCE.md)。

## 折叠、节点拖动与自定义上下文

- 直线模式的每个子 Agent 都能独立折叠为摘要卡；父分组折叠时隐藏嵌套分组，Token 汇总持续更新，新记录不会自动展开。
- 创建 Agent 的工具节点使用黄色连线连接该 Agent 的首节点或折叠摘要；Fork 额外保留继承切点虚线。
- 按住鼠标中键拖动圆形气泡，带动本链后续节点和由这些节点创建的 Agent 分支。移动量按缩放比例换算。
- 布局偏移绑定稳定节点 ID，新节点继承其祖先偏移；更新不会清除手动布局。折叠状态和偏移按会话保存在当前浏览器。
- “重置节点”清除布局偏移；“重置视图”只重置镜头位置和缩放。
- 后续上下文整理模块可使用 `bubblingContextSources` 服务发布可观察数据。字段、生命周期和示例见 [CONTEXT-SOURCE.md](CONTEXT-SOURCE.md)。它只控制可视化，不执行模型提示词注入。

## Agent 分支（直线模式）

- 主 Agent 与子 Agent 并列为独立列；较多分支可拖动画布横向查看。
- 新建子 Agent 从自己的记录起点开始，通常以灰色系统提示词开头，首节点与创建工具所在行对齐。
- Fork 使用宿主 Session 的精确 `inheritedEventCount`，继承历史不重复绘制；虚线连接父列的继承切点与子列新增记录。
- 支持递归发现嵌套子 Agent、实时跟随各自轨迹和 Token 汇总。只保留只读 Client 会话引用，不创建或唤醒 Agent，不调用模型。
- 创建关联通过父日志 catalog / 工具调用及工具返回确认。并行创建无法确认时明确提示，绝不按时间随意连线。缺失父历史切点时可先加载更早记录；子列也提供加载历史按钮。
- 主 Agent 和各子 Agent 分别汇总自身日志中模型报告的用量；Fork 继承前缀另列为已加载内容估算，不重复累加到新增用量。各次调用的输入总和是调用消耗，可能重复包含相同上下文，不等于独立内容大小。
- 此版本更新了宿主插件入口，安装后需要重启 DSH 以注册 `bubblingContextLineage` 投影，单纯刷新网页不足以启用分支服务。

运行 `npm test` 验证继承边界、分支布局、工具归属与订阅清理。

## 使用

点击会话右上角、“在应用中打开”左侧的气泡按钮，打开原生右侧面板。

- 灰色：系统提示词 / 工具定义。
- 蓝色：用户输入；绿色：注入的上下文。两者的圆形节点更大。
- 紫色：助手消息，包含文本、推理和 Tool call；橙色：工具调用及结果。两者节点更小。
- 标题栏关闭按钮左侧可切换“直线 / 蛇形”，记住浏览器中的选择；蛇形沿斜向路线持续向下、左右折返。
- 每个节点的数据放入同色细边框卡片，以短线连接气泡；点击卡片同样打开详情。
- 基础节点间距为 40px，大节点相邻时自动增距以防重叠；说明和 Token 数使用紧凑排版。
- 新调用沿现有节点从头快速传递高亮，随后新气泡依次出现。
- 流式输出更新同一个节点；工具完成更新原工具节点，避免重复气泡。
- 点击节点或用 Enter / 空格打开详情，查看内容、调用参数、结果及原始记录。
- 在画布空白处按住鼠标左键可自由拖动，滚轮以鼠标所在位置为中心缩放（15%–300%）；点击节点仍打开详情。
- 新节点和分支更新不会自动移动或缩放视图。可主动点击“定位最新”或“重置视图”，通过“加载更早记录”补齐历史。
- 按系统“减少动态效果”设置关闭动画。

## 数据与 Token 的含义

使用 DSH 的 `useTrajectory` / `useSession` 标准订阅。复用宿主实时数据，不轮询、不额外调用模型、不修改对话。插件前端依赖内置 trajectory 模块，无需先切换到“轨迹”标签。

DSH 按调用提供 usage，并不提供每条上下文的精确 Token 及缓存归属：

- 助手输出有 `outputTokens` 时显示实报值。
- 其他节点按文本字符粗略估算，标记 `≈`；不是模型 tokenizer 或计费数。
- 每个节点的“累计”是从已加载起点至该节点的轨迹内容 Token 总量估算，包含历史与工具记录，不代表模型当前上下文长度、KV 缓存或压缩后的有效输入。
- 只有调用实报的 `cacheReadTokens` / `cacheWriteTokens` 才显示为实际缓存读写；缺失显示“未报告”，不当成零，也不推算分配给历史节点。
- 压缩检查点显示为绿色节点并有说明，历史仍可追溯。

## 开发与安装

目标运行时：DSH 0.2.0-rc.2。需要 Node.js >=22.19。前端使用宿主 React，构建没有外部依赖。

```bash
npm run build
dsh plugin --profile web add /home/platanus/DSH-BubblingContext
```

刷新 DSH 页面；配置或包元数据没有热更新时重启 DSH。不要反复安装依赖来刷新界面。

## 文件

- `src/index.js`：宿主入口。
- `src/trajectory.cjs`：轨迹数据转换、稳定节点 ID、Token 展示规则和布局。
- `src/client.cjs`：按钮、实时气泡面板、动画和详情。
- `scripts/build.mjs`：把数据模块与界面构建成 DSH 惰性客户端 bundle。
- `lib/client.js`：预构建产物，随仓库交付。
- `cordis.patch.yml`：Profile 插件配置层。

此版本显示线性执行轨迹；白线表示发生顺序，不表示严格因果依赖或所有记录始终留在模型上下文中。
